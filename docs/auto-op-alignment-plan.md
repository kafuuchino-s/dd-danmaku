# 自动 OP 对齐方案

## 背景

DandanPlay 的 `/match` 返回虽然带 `shift` 字段，但实际命中经常是 `0`，不足以解决当前片源与弹幕基准版之间的固定时间偏移。仓库现有能力是按季度记忆的手动 `timelineOffset`，它仍然保留并作为最终兜底。

当前自动 OP 对齐的目标不是替代手动轴偏秒，而是在**不污染手动季度偏移语义**的前提下，为每次播放增加一个自动估算层：

- 优先利用 Emby `Chapters` 中的 `IntroStart` / `IntroEnd`
- 在片头附近用 OP 相关弹幕做检测
- 先找**靠近 Intro 起点的早期可靠锚点**，再考虑窗口聚类
- 当前集不可靠时，再回退到**季度自动基线**或手动季度偏移

## 当前实现概览

### 1. 运行时状态与开关
- 自动 OP 对齐默认开启，开关走 `lsKeys.autoOpAlignEnable`
- 运行时状态：
  - `window.ede.autoTimelineOffset`
  - `window.ede.autoTimelineOffsetMeta`
  - `window.ede.introInfo`
- 最终解析偏移：
  - `getEffectiveTimelineOffset() = 手动季度偏移 + 自动偏移`

### 2. Intro 标记来源
优先从以下位置读取片头标记：
1. 当前 item 的 `Chapters`
2. 完整 item 的 `Chapters`

仅接受：
- `MarkerType === 'IntroStart'`
- `MarkerType === 'IntroEnd'`
- `end > start`
- Intro 时长落在 `50s ~ 110s`

否则视为无效 Intro，不能直接自动对齐。

### 3. 弹幕检测窗口
自动检测只在片头附近工作，不扫描整集：

- 搜索窗口：`[max(0, introStart - 25), min(introEnd + 25, introStart + 120)]`
- 正向关键词：`op`, `opening`, `片头`, `片头曲`, `空降`, `跳op`, `不跳op`, `开场`
- 负向关键词：`ed`, `ending`, `片尾`
- 强关键词：`op`, `opening`, `片头`, `片头曲`, `不跳op`
- 跳过类关键词：`空降成功`, `空降`，以及 `跳op`（但 `不跳op` 不算跳过类）

## 当前策略：早期锚点为唯一自动应用路径

### 4. 为什么只用“早期锚点”来做单集自动校准
旧策略虽然保留了 5 秒分桶 + 15 秒滑动窗口评分，但只要允许把最佳窗口里的关键词中位数直接拿来应用，就还是会被“大家已经听了十几秒 OP 后才开始集中刷 `OP好听 / 不跳OP`”这类晚热点带偏。

这类窗口能说明“这里很像 OP 讨论区”，但不一定说明“这里就是 OP 开始时刻”。单集自动校准真正要找的是**靠近 Intro 起点的第一个可靠信号**，因此当前实现收敛为：

1. 仍然保留窗口评分与 top windows，作为调试信息
2. 但**只有早期锚点**可以触发当前集自动应用
3. 只要没有命中早期锚点，就直接回退到季度自动基线或手动季度偏移

### 5. 早期锚点规则（当前唯一应用策略）
先从片头窗口中提取所有**强关键词**弹幕，再检查下面的早期区间：

- 早期锚点区间：`[introStart + 5s, introStart + 12s]`

命中条件：
- 命中至少 `2` 条早期强关键词；或
- 只命中 `1` 条，但整段片头窗口内的强关键词总数至少 `8` 条

一旦满足条件：
- `opClusterTime` 取**该区间内最早的一条强关键词弹幕时间**
- `autoOffset = introStart - opClusterTime`
- `clusterStrategy = early-anchor`
- `confidence = 1`

这样做的目的不是找“讨论最密集的时间”，而是找“第一个足够可信的 OP 开始信号”。

### 6. 时间窗口评分的角色（仅调试）
当前仍保留 5 秒分桶 + 15 秒滑动窗口评分，以及：
- 关键词/强关键词命中数
- 加权关键词占比
- 关键词占比
- 离 `IntroStart` 的距离惩罚
- `IntroEnd` 之后的惩罚
- 跳过类关键词惩罚
- 弹幕总量惩罚

这些结果只用于：
- 看片头附近的讨论分布
- 分析为什么没有命中早期锚点
- 给季度自动基线诊断提供上下文

**不会**直接触发当前集自动应用。

### 7. `IntroStart = 0` 的当前语义

`IntroStart = 0` 仍然经常意味着服务端把“文件开始”粗略标成了 Intro，但在当前策略里它已经**不需要单独的窗口保护分支**：

- 单集自动应用只看早期锚点
- 早期锚点要求命中 `introStart + 5s ~ +12s` 的强关键词
- 因此像第 7 / 10 集这类“30 秒以后才出现 OP 热点”的情况，会自然因为**没有早期锚点**而回退

也就是说，现在对零起点误判的防御，已经内化进“只认早期锚点”这条规则本身。

## 季度语义与缓存策略

### 8. 手动季度偏移语义保持不变
手动 `timelineOffset` 仍然是用户长期基线：

- 继续按季度读写
- 继续由用户手调触发写入
- 不允许自动逻辑改写这份手动缓存

### 9. 季度自动基线单独缓存
当前实现已经支持**独立于手动偏移**的季度自动基线：

- 单独写入 `_season_auto_timeline_offset_`
- 与手动季度偏移完全分离
- 缓存带版本号，策略升级后会自动失效重算

季度自动基线只用于：
- 当前集无 Intro 标记时
- 当前集自动检测失败时

聚合规则分两层：

#### 标准季度基线
- 只吸收 `status = applied` 且 `confidence >= 0.85` 的样本
- 对样本偏移取中位数
- 删除偏离中位数超过 `4s` 的离群值
- 至少保留 `3` 个样本才生成季度自动基线

#### 稀疏弹幕季度基线（保守模式）
用于弹幕较少、整季很难凑满 3 个常规样本的情况，但仍然**不降低单集自动应用门槛**。

只在以下条件同时满足时启用：
- 样本本身已经 `applied`
- `confidence = 1`
- `clusterStrategy = early-anchor`
- 至少有 `2` 个样本
- 样本偏移彼此非常接近（离中位数不超过 `1.5s`）

也就是说，稀疏番不是“放宽单集检测”，而是“只要已经拿到少数几个非常硬的早期锚点样本，就允许它们保守地支撑整季基线”。

所以现在的语义是：
- 手动季度偏移 = 用户长期基线
- 当前集自动偏移 = 本次播放的运行时增量
- 季度自动基线 = 当前集失败时可复用的自动兜底层
- 最终偏移 = 手动季度偏移 + 自动偏移（当前集或季度基线）

## 当前回归观察（夜樱四重奏 花之歌 S1）

### 10. 有 Intro 且命中可靠的集数
当前高置信命中样本：

- 第 1 集：`-5.363s`
- 第 4 集：`-6.423s`
- 第 5 集：`-6.326s`
- 第 8 集：`-6.751s`
- 第 11 集：`-6.579s`

共同特征：
- 都能在 `IntroStart + 5s ~ +12s` 内找到可靠强关键词
- 使用的都是 `early-anchor`
- 偏移已经明显收敛到 `-5s ~ -7s`

其中：
- 第 4 集的早期锚点只有 `1` 条，但整段片头窗口内强关键词很多，因此允许作为单点锚定
- 第 5 / 8 集都存在“后面更热的 OP 评论簇”，但当前策略会优先取更早的锚点，不再被热度带偏

### 11. 有 Intro 但当前仍回退的集数
当前有 Intro 但没有进入可靠样本的集数：

- 第 2 集：`IntroStart = 0`，候选热点偏晚且互相接近，未命中早期锚点，回退
- 第 3 集：存在 OP 评论，但主要集中在 `IntroStart` 很后面，缺少早期锚点，回退
- 第 6 集：只有零散关键词，最佳窗口关键词数不足，回退
- 第 7 集：`IntroStart = 0`，旧策略会误落到 30 多秒后的热点；当前会因为没有早期锚点而直接回退
- 第 10 集：`IntroStart = 0`，20~40 秒附近有大量 OP 评论，但它们更像“晚热点”而不是 OP 起点；当前会因为没有早期锚点而回退
- 第 12 集：关键词过少，且没有 `+5s ~ +12s` 的早期锚点，回退
- 第 13 集：片头附近只有极少量关键词，无法形成可靠窗口，也没有早期锚点，回退

这些回退的共同点是：
- 不是完全没 OP 相关弹幕
- 而是**缺少足够可信的“早期起点信号”**
- 当前策略宁可回退，也不接受晚热点造成的大偏移误判
- 如果后续同季度已有少量但高度一致的早期锚点样本，这些回退集可以复用**稀疏弹幕季度基线**，但不会因此放宽它们自己的单集检测条件

## UI 与调试信息

### 12. 调试信息展示
在 OSD 和“弹幕信息”里应展示：
- 自动对齐是否启用
- Intro 起止秒数
- `clusterStrategy`（当前自动应用时固定为 `early-anchor`；未命中时仅作为调试上下文）
- 当前集自动偏移
- 季度自动基线样本数与基线值
- 季度基线策略（`standard` / `sparse-early-anchor`）
- 最终偏移
- 回退原因

Console 日志应至少保留：
- Intro 是否命中
- 最佳候选窗口
- 是否命中早期锚点
- 当前集为何 applied / fallback
- 是否回退到季度自动基线

## 回退策略

- **无 Intro 标记**：优先尝试季度自动基线；若无季度基线，则完全沿用手动季度偏移
- **有 Intro，但没有早期锚点**：直接回退到季度自动基线或手动季度偏移
- **`IntroStart = 0` 且缺少可靠早期锚点**：视为可疑标记，禁止自动应用
- **偏移超过安全范围**：放弃自动对齐
- **季度自动基线样本不足或分布发散**：不建立季度自动基线
- **弹幕稀少但已有少量高度一致的早期锚点样本**：允许建立 `sparse-early-anchor` 季度基线；若连这层也不满足，则继续回退手动季度偏移

## 验证步骤

1. **可靠早期锚点场景**
   - 选择第 1 / 4 / 5 / 8 / 11 集
   - 确认结果落在 `-5s ~ -7s` 左右
   - 确认 `clusterStrategy = early-anchor`

2. **零起点保护场景**
   - 选择第 7 集或第 10 集
   - 确认不会再落到 `-30s` 一类的大偏移
   - 确认结果为回退而不是误命中

3. **关键词稀疏场景**
   - 选择第 6 / 12 / 13 集
   - 确认因为关键词不足或没有早期锚点而回退

4. **季度自动基线场景**
   - 在已有可靠样本后，验证季度自动基线是否收敛到约 `-6.4s`
   - 验证当前集失败时会回退到季度自动基线，而不是污染手动季度偏移

5. **稀疏弹幕季度基线场景**
   - 选择弹幕较少、但至少有 2 集已经命中 `early-anchor` 且偏移接近的季度
   - 验证可以建立 `sparse-early-anchor` 基线
   - 验证当前集自己证据不足时可以复用该季度基线，但不会放宽单集自动检测阈值

6. **用户手动修正**
   - 在自动结果基础上再点 `+1/-1`
   - 确认最终偏移仍是“手动 + 自动”
   - 确认手动部分仍按季度保存
